Which page-one pages under-capture clicks? A position-adjusted CTR opportunity model

Swapnil Yadav · Machine Learning Engineering Intern, FlyRank AI (July 2026 cohort)
Indian Institute of Information Technology, Manipur · Repository
CTR / Engagement Opportunity Scoring decision-support client-holdout validation

Abstract

Among pages that already rank on Google's first results page, which ones earn far fewer clicks than their search position would predict, and therefore deserve a title or snippet review first? Using the FlyRank ML Internship search dataset — a pseudonymized release of ~79 million daily Search Console records, with a 30,000-page, 32-client anonymized slice used here — I define an expected CTR for every page from pre-click signals (position, content type, age, volume) and rank pages by the gap between expected and actual CTR. Against a transparent position-tier-median baseline, a gradient-boosting model improves calibration on held-out clients (R² 0.001 vs -0.242) but only ties the baseline at the very top of the queue, so the shippable scorer stays the readable rule. The honest finding is a validation one: a naive random split reported R² 0.143, but a client-grouped split collapsed it to 0.001 — most of the apparent "skill" was memorizing clients. The output is a 3,237-page, human-reviewed content-action queue with reason codes — a triage aid for editors, not an automated system.

1. Introduction & problem

A content team can only review so many pages a week. A page sitting at position two that earns a near-zero click-through rate is leaving clicks on the table — but a page at position nine with the same CTR may be perfectly normal. The decision this work supports is narrow and practical: which visible pages should an editor open first for a title, meta, or snippet review. The unit of analysis is one content page; the output is a ranked queue with a reason a human can inspect; the action is a human edit; the cost of a wrong pick is wasted review time and the risk of changing a page that was fine. Data helps because "low CTR" only means something relative to position, and adjusting for that across tens of thousands of pages is not something a single threshold can do.

2. Data

The work uses the FlyRank ML Internship release. The full warehouse holds roughly 79 million daily Search-Console/GA4 rows across 104 pseudonymized clients (build v20260703, daily facts through 2026-06-30); the analysis and figures here run on the shipped anonymized slice of 30,000 pages across 32 clients, with all metrics aggregated over a trailing 90-day window. Every identifier is pseudonymized and used only for grouping.

Deliberately excluded (public-safe and leakage-safe): the label-derived trend fields (trend_direction, trend_pct); clicks_90d as a feature (clicks ÷ impressions is CTR — including it reconstructs the target); FlyRank's product decision flags (not shipped in the release by design); and any raw URL, query, title, or client name (never present, never reconstructed).

3. Methodology

Task. Ranking / scoring — "which pages first?" — built on an expected-CTR regression and ranked by residual (predicted minus actual CTR).

Review population. The pages the lane actually acts on: visible (impressions_90d ≥ 500), ranking on page one (avg_position 1–20), and earning some clicks (ctr > 0) — 10,807 pages. CTR is clipped at its 99th percentile to tame a heavy tail; seeds fixed at 42.

Features (pre-click, leakage-safe): average position, log impressions, content age, days since last update, word count, search volume, competition, CPC, content type, main intent. Target: the page's CTR (a same-window scoring proxy; a future-window outcome is the warehouse upgrade). Baseline: the position-tier median CTR — the transparent Week-4 rule, fit on training clients only. Validation: a client-grouped split (GroupShuffleSplit, 25% held out) so every test page comes from a client the model never saw. Leakage checks: a feature inventory against a banned list, and a confession test — adding clicks_90d spikes R² to ~0.98, the signature of the answer in disguise, confirming it stays out.

4. Results

On held-out clients, the learned models predict CTR slightly better than the tier-median baseline on absolute error, and clearly better on variance explained, but the gains are modest — a depth-5 tree ties gradient boosting on MAE, so complexity is not rewarded for its own sake.

On unseen clients the model's absolute-CTR accuracy is only directional, barely ahead of a simple tier median. So the shippable scorer stays the transparent rule; the model is kept as a calibration cross-check for the middle of the list.

5. Limitations & honest framing

  • This is observational, built on one 90-day snapshot. It surfaces pages that look worth reviewing; it does not establish that editing a title causes more clicks — that needs an experiment.
  • Feature and target share the 90-day window, so this is opportunity scoring, not future prediction.
  • The held-out client count is small, so the model numbers are directional; the full warehouse is where the design would be re-earned.
  • No claims about Google's ranking algorithm or AI rankings; no client-identifying output anywhere.

6. Ranked recommendations (the action playbook)

The output is a 3,237-page human-reviewed action queue, scored by gap × log(impressions) and tagged by archetype. Value is framed as exposure at stake: the top 50 pages alone carry 2,015,419 impressions/90d that currently under-convert relative to their position peers.
